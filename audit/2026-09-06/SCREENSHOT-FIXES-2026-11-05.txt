Implemented

- Draft quote editor now has explicit price/item editing: add/remove items,
  descriptions, fractional quantities, GBP unit prices, explicit tax percent,
  live line/subtotal/tax/total preview, save, cancel and keep-saved-pricing.
  Initial tax is deliberately blank because saved legacy conventions vary.

  Free items and zero tax are supported; partial numbers, negative amounts,
  non-finite values, excessive precision and overflow are rejected.

  line totals, subtotal, percentage tax rate, tax amount and grand total in
  one UPDATE; client-supplied totals cannot override this calculation. Price
  writes require draft status and the loaded updated_at version. Both are
  predicates on the mutation, along with actor/id ownership. Concurrent
  changes return 409. Ordinary read failures return 500 rather than 404.
- List response adds updated_at and pricing_edit_version:1; old API responses
  do not enable price editing. Price-capable API and mobile must be released
  together; no deployment was performed. No new permission or beta bypass.
- Editor keeps failed edits inline for retry, blocks duplicate saves, locks
  inputs during saving, hides send/edit actions while editing, and reloads
  saved data. A conflict keeps edits visible for comparison and offers an
  explicit discard/reload action before another save. Both canonical and
  older snake_case item names/prices prefill without inventing missing data.
- Send endpoint now performs a draft/version-conditional status update before
  its email call; a concurrent price edit cannot send the earlier amount.
  New mobile sends the reviewed version; older callers use the version read
  by the server. Database predicates retain full timestamp precision, with
  a null-version predicate for legacy rows. Non-draft sends return conflict.
  The API returns the saved quote, matching the existing mobile service type.
  Conflict reloads the mobile quote for review. All email calls in tests are
  mocked: no actual email was sent.
