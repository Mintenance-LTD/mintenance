P1 · R01

P1 · R02

Weekly payout lacks durable pre-transfer journal

Pending balance is zeroed and lifetime paid increased before Stripe call. Crash before call can strand funds. Lost success response enters restore path; weekly idempotency key later changes. Restore uses read-then-write without concurrency guard.

Evidence: apps/web/lib/stripe/connect/payouts.ts:167-327

Required action: Persist stable payout reservation/operation; reconcile uncertain provider result; atomic recovery. Test crash, timeout, new-credit and week-boundary cases. Confirmed code risk, not exercised with real money.

P1 · R03

Deletion can erase unpaid contractor balance

API excludes completed escrow from blockers and never checks pending payout balance. Production deletion functions delete profile; payout balance FK cascades. A contractor with only released-but-unpaid earnings can lose the balance.

Evidence: api/user/delete-account/route.ts; production delete_user_data and payout FK

Required action: Block or safely settle/journal pending balance atomically; retain required financial records. No account deleted during audit.
